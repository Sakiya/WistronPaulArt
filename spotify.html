Spotify 嵌入比較

方法一為靜態 iframe；方法二為官方 iFrame API（曲目清單由腳本陣列產生，可擴充多首）；方法三為 Web API（與 iFrame API 不同，用於自訂 UI／metadata）。方法一目前嵌入曲目 ID：3Oic0krCmH6zKqMjUufvBb。

方法一：靜態 <iframe>（分享 → 複製嵌入）

無法用外層 CSS 改 iframe 內部；僅能調 width、height、style、allow、title 等屬性。

方法二：官方 iFrame API（iframe-api/v1）

官方文件：iFrame API 參考。 腳本載入後會呼叫 window.onSpotifyIframeApiReady，再以 IFrameAPI.createController(元素, { uri, width, height }, callback) 建立與靜態嵌入相同的 Spotify 播放器介面。

EmbedController 常用能力（文件列舉）： loadUri(uri) 載入內容； play()、pause()、resume()、togglePlay()、restart()； seek(seconds)（多見於 podcast 情境）； destroy() 移除嵌入。 事件：ready、playback_started、playback_update（含 isPaused、position、duration 等）。 play() 無使用者操作時可能被瀏覽器擋 autoplay。

多首並列時，點任一首的播放或當某首開始播放時，會自動暫停其他首（同一時間僅一首在播）。

外層進度條可拖曳／點擊至整首長度（catalogTotalMs）並對嵌入呼叫 seek；若實際音訊仍約 30 秒就停，代表 Spotify 仍在預覽／加密播放未就緒，請見下方橘色提示並檢查 encrypted-media 與主機政策。

外層進度條右側總時長會取 Math.max(API 的 duration, catalogTotalMs)。請維護下方腳本內 IFRAME_API_PLAYER_ROWS（每筆 trackId、label、catalogTotalMs；選填 trackName、artistName）。播放器 DOM 由程式依陣列長度自動產生。catalogTotalMs 為 0 時外層總長僅跟 API。

部署於有 Content-Security-Policy 的主機時，請一併放行 https://open.spotify.com 於 script-src（或 script-src-elem）與 frame-src，否則官方腳本或嵌入框會被瀏覽器擋下。

方法三：Web API（Client Credentials）+ preview_url

此段僅作對照示範（與 iFrame 嵌入無關），實務上不建議採用
此方式上線：須使用 Spotify Client Credentials 向 api.spotify.com 取曲目 JSON，再以 <audio> 播放 preview_url（多數曲目可能沒有 30 秒預覽）。 頁尾 Web API script 中的 const clientId／const clientSecret僅方便本機對照；Client Secret 絕不可寫在公開前端（外洩、被爬蟲帶走、版本庫永久留痕），正式環境應由後端保管 Secret、換取短期 access token 再提供給前端或改走其他授權流程。 此外，瀏覽器直接對 https://accounts.spotify.com/api/token 發 POST 換 token，常會被CORS 政策擋下而無法取得 token；程式亦以佔位字判斷是否略過請求。綜合安全性與token 取得受阻，本區塊建議只當文件閱讀，產品請優先採方法一／二。
